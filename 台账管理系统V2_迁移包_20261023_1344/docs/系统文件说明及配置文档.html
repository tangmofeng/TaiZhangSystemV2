文件作用何时使用
install.bat迁移安装器：自动申请管理员权限 → 定位同目录迁移包 .zip → 备份旧目录（改名为 TaiZhangSystemV2_old_日期时间）→ 解压 → 定位 Python（312/311/310 依次探测，找不到自动下载安装 3.12）→ pip 安装依赖（清华镜像 → 官方源 → wheels 离线包三级回退）→ 写 start_server.vbs + 注册开机自启（HKCU Run）→ 放行防火墙 8090 → 启动服务并验证端口 → 输出本机/局域网访问地址新机器部署 / 整机迁移，右键管理员运行
install.ps1install.bat 的 PowerShell 辅助（提权、端口检测、解压等逻辑的承载脚本）由 install.bat 自动调用，无需手工运行
pack.ps1发布打包器：清理临时文件 → 建打包目录（台账管理系统V2_迁移包_时间戳\）→ 复制正式文件（server / public / docs / wheels / install.bat 等，不含真实 data 数据目录）→ 压缩为 D:\台账管理系统V2_迁移包_yyyyMMdd_HHmm.zip本机发布新版本时在项目根目录运行

watchdog.py看门狗：每轮检测 127.0.0.1:8090 端口是否可连且存在 server\app.py 的 pythonw 进程；服务掉线则自动拉起并写日志（防止误判双实例）可加计划任务周期运行，或手动执行一次
watchdog.log看门狗运行记录（时间 + "服务正常 / 检测到服务掉线，正在自动拉起…"）排查服务是否被自动拉起过

七、数据备份与恢复

7.1 自动备份

系统在服务启动时与每日定时线程执行自动备份，产物为 data\backup\system_yyyyMMdd_HHmmss.db（SQLite 在线备份，无需停服），保留最近 14 份，更早自动删除。备份记录（文件名/大小/结果）写入 backup_logs 表，可在 系统管理 → 备份管理 查看与手动备份（/api/backup、/api/backups）。

7.2 手动快照（回滚点）

重大改造前手工复制 system.db 到 data\system_backup_日期_before_事项.db。当前保留：system_backup_20261023_before_planA.db（耗材区域+库位改造前）、system_backup_20261023_before_con_pos.db（库位方案准备前）。

7.3 恢复方法

  1. 停止服务（任务管理器结束 pythonw.exe 中运行 server\app.py 的进程，或任务栏图标右键退出）
  2. 把选中的备份文件复制覆盖 data\system.db（先备份当前 system.db 以防万一）
  3. 重新启动服务（start_server.vbs 或开机自启）

八、修改数据方法

  • 业务数据（台账/库存/发放/出入库等）：网页对应模块增删改、批量导入导出（耗材/备件/打印机模板导入导出）
  • 列顺序/显隐：表格表头右键"列设置"，admin 保存后全员同步
  • 用户密码重置：见《故障处理手册》（管理员在系统管理-账号管理重置）
  • 直接改库：用 DB Browser for SQLite 打开 data\system.db（改前先复制一份备份；改后重启服务；合计库存等冗余值由系统自动重算，勿手工改错）

九、常见问题快速定位

问题排查入口
网页打不开/服务未启动netstat -ano | findstr 8090 看监听；双击 start_server.vbs 手动启动；看 watchdog.log 是否自动拉起过
前端功能异常（页面空白/按钮无效）版本自检会自动重载；强制刷新 Ctrl+F5；确认 public\js\app.js 顶部 CUR 与 index.html 的 ?v= 一致（每次改代码两处同步递增）
需要回滚数据库用 data\backup\ 最近备份或 20261023 迁移前快照覆盖 data\system.db 后重启
磁盘空间被日志占满data\access_*.log 归档文件可手动删除（当前 access.log 保留）；backup 目录会自动保持 14 份
局域网其他电脑访问不了防火墙规则 TaiZhangSystem8090 是否放行；用 http://本机IP:8090 而非 127.0.0.1
